ServiceNow MCP Apps for Microsoft 365 Copilot

A stateless TypeScript MCP server that turns ServiceNow catalog ordering, request approvals, and incident management into secure, interactive experiences inside Copilot.

Capability surface

Atomic tools, purpose-built widgets

The model selects narrowly scoped tools. Each user-facing result carries structured data for a corresponding MCP App instead of verbose JSON or a replicated ServiceNow interface.

Identity and trust

Calls run as the person in the conversation

The default production pattern validates the inbound Copilot token, exchanges it through Entra On-Behalf-Of, and presents a downstream token that ServiceNow maps to sys_user.

  1. Copilot authenticates the userThe declarative agent obtains an access token for the MCP API.
  2. The Function validates the bearer tokenIssuer, audience, tenant, and signing keys are checked before tool execution.
  3. MSAL performs OBO exchangeThe inbound assertion becomes a token for the ServiceNow-trusted downstream audience.
  4. ServiceNow maps the identitypreferred_username resolves against sys_user.email, enforcing native ACLs and authorship.

Security posture

Secrets are referenced from Key Vault, deployment storage is private, and the Flex Function reaches Blob packages through VNet integration and a private endpoint.

  • ✓ No secrets committed
  • ✓ Per-user ServiceNow ACLs
  • ✓ Private deployment storage
  • ✓ Application Insights telemetry

Build and operate

From clone to Copilot-ready

The repository ships the application, Azure infrastructure, M365 agent package, repeatable tests, and policy-aware release automation as one versioned unit.

Terminal · repository root
# Install and validate locally
npm install
npm run build
npm test

# Validate ServiceNow surfaces
npm run preflight:readiness

# Deploy through the human test boundary
npm run release:auto -- \
  --environment snowmcpwidg-dev

# Prepare a repeatable approval demo
npm run demo:seed
npm run demo:verify
  1. Provision ServiceNowCreate the OAuth app and least-privilege integration identity, then establish OIDC trust for OBO.
  2. Provision AzureBicep creates Flex Consumption, Key Vault, private storage connectivity, and observability.
  3. Publish the agentAgents Toolkit validates and updates the existing M365 app package without duplicating OAuth registration.
  4. Prompt-test in CopilotThe automated path stops deliberately where a human starts a new conversation and verifies the experience.

Repository anatomy

One repo, explicit ownership boundaries

Runtime, ServiceNow integration, widgets, infrastructure, tenant packaging, and tests are separated so changes can stay narrow while contract parity remains enforced.

  • src/tools/One MCP tool per module and the central manifest drift guard.
  • src/services/ServiceNow REST, token management, catalog, request, cart, and incident behavior.
  • src/ui/widgets/Self-contained widget sources, host bridge, registry, and generated modules.
  • infra/Azure Flex Consumption, identity, storage, networking, Key Vault, and monitoring.
  • m365-agent/Declarative agent manifest, plugin snapshot, tool declarations, and ATK lifecycle.
  • test/Behavior, auth, manifest parity, widget resources, and structured-content contracts.
Contract invariant

Tool and widget lockstep

A tool change is complete only when runtime registration, Zod schema, minimal manifest, widget binding, tests, and M365 package snapshots agree.
